# Product Requirements Document

## 1. 产品概述

MView 是一个自托管的个人媒体浏览系统。

第一版 MVP 聚焦为：

> 读取 Linux 服务器上的本地 JMComic 下载目录，并通过 Web 页面提供只读漫画浏览与阅读能力。

长期目标是扩展为可浏览漫画、图片、视频的个人媒体系统。

## 2. 用户

第一版仅面向一个用户：

- 用户本人
- 通过局域网或校园 VPN 访问
- 使用桌面或移动浏览器访问 Web 页面

第一版不支持注册、多用户、访客、分享链接或权限分组。

## 3. 使用场景

### 3.1 浏览漫画库

用户打开 Web 页面后，可以看到本地已下载的 JM 漫画列表。

列表需要展示：

- 漫画封面
- 漫画标题
- Album ID
- 作者
- 标签
- 页数
- 更新时间

### 3.2 查看漫画详情

用户点击某本漫画后，可以进入详情页。

详情页展示：

- 标题
- 作者
- 标签
- 页数
- 发布时间
- 更新时间
- 简介
- 章节列表

### 3.3 阅读漫画章节

用户点击章节后进入阅读器。

阅读器需要：

- 显示该章节所有图片
- 按自然顺序排列图片
- 支持纵向滚动阅读
- 支持图片懒加载
- 支持返回详情页
- 支持章节切换

### 3.4 刷新本地漫画索引

用户可以手动触发后端重新扫描 JM 本地目录。

第一版不要求自动定时扫描。

## 4. 功能需求

### 4.1 登录

第一版需要基础单用户登录。

要求：

- 用户名和密码从环境变量读取。
- 不提供注册。
- 不提供多用户管理。
- 登录后的 API 请求需要鉴权。
- 不允许未登录用户访问漫画数据和图片内容。

### 4.2 本地漫画扫描

系统需要扫描配置的 JM 图片根目录：

```txt
JM_IMAGE_ROOT=/mnt/hdd/JMDownload/images
```

识别规则：

- 根目录下一级目录视为候选 album。
- 存在 `album_data.json` 的目录才视为有效 album。
- 章节目录根据 `album_data.json` 的 `episode_list` 和实际目录共同识别。
- 图片文件按自然顺序排序。

### 4.3 元数据解析

系统需要读取 `album_data.json`。

解析原则：

- 字段存在则读取。
- 字段缺失则降级。
- 不因单个字段异常导致整个服务崩溃。
- 保留原始 JSON 供后续扩展。
- `episode_list` 可能是字符串形式的 Python tuple，必须安全解析。
- 禁止使用 `eval`。

### 4.4 图片读取

系统需要提供安全图片读取 API。

要求：

- 前端不得直接接收服务器绝对路径。
- 后端必须验证请求路径位于 `JM_IMAGE_ROOT` 内。
- 必须防止路径穿越。
- 图片接口必须受登录保护。

### 4.5 搜索

MVP 可以支持基础搜索：

- 按 Album ID 搜索
- 按标题搜索
- 按作者搜索
- 按标签搜索

如果开发成本需要收敛，搜索可以先只支持 Album ID 与标题。

## 5. 非功能需求

### 5.1 安全

- 不公网暴露作为第一目标。
- 即使仅局域网访问，也必须有基础登录。
- 不允许任意文件读取。
- 不允许直接暴露服务器绝对路径。
- 不提交真实媒体文件、真实配置或密钥。

### 5.2 性能

- 漫画列表应避免一次性加载所有图片原图。
- 阅读器应使用图片懒加载。
- 后端扫描应能容忍一定规模的本地漫画目录。
- 第一版可以采用内存索引或按请求扫描，不使用数据库。

### 5.3 可维护性

- 后端扫描、元数据解析、图片服务、安全检查应分层。
- 前端页面、API 调用、组件应分层。
- 第一版不做复杂抽象，但要避免写死单个 album 示例。

## 7. 验收标准

第一版 MVP 完成时应满足：

1. 可以登录系统。
2. 可以扫描本地 JMComic 下载目录。
3. 可以看到漫画列表。
4. 可以打开漫画详情页。
5. 可以看到章节列表。
6. 可以进入章节阅读器。
7. 图片按正确顺序显示。
8. 未登录不能访问 API 和图片。
9. 路径穿越请求被拒绝。
10. 系统不修改原始媒体文件。
